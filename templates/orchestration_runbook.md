# 実行手順書(オーケストレーション・ランブック)— v1.6

> pot_A/pot_B の実走で確立した実行層の手順。**このセッション固有のアドホック運用を再現可能にする**のが目的(型の法は rules.md、壺の起動は templates/README が正典。本書はその間の「壺師が実際に何をどの順で走らせるか」)。

## 役割とモデル(推奨)
壺師=上位モデル(メインコンテキスト)/蟲師・補助課・課=軽量モデル(サブエージェント並列)/**目付=壺師と異なる基底モデル**(v1.6)。全て実行時モデルを state に記録。

## 標準シーケンス(1壺)
```
Stage0: templates→pot_X生成(shared_context v1・state・与件出所付き)→commit
Stage1: task_S1_XX.md 発行(毒の翻訳=引用付き)→ 蟲師N機並列(プロンプト=shared_context+task+書式のみ・他ファイル読取禁止)
        → progress着弾ごとにcommit
統合1:  補助課(クラスタタグ分担・境界二重割当)並列 → 【目付検分=定型指示書】(KILL合法性・台帳独立再計数・毒翻訳突合・リンター)
        → 壺師批准(畳み・違法KILL復活)→ 乱数圧縮(種記録)→ integration_SN.md+state更新 → commit
Stage2: task_S2_XX.md 発行 → 蟲師並列(関所・算盤=算式義務・近傍変種)→ 着弾commit
        → 【目付検分】(判定合法性・算式再計算・★計数)※部分完了はここで検出→再開規定(再走・再採番)
Stage3: 決勝抽選(★縮退時は一様・種記録)→ からくり(生成専任)→ 客観課(からくり適用後を判定)…直列
        → 壺師組み立て: 安全帳票(2区分)+決勝資料(乱数提示順・恒久ID分離・同格欄・正本参照方式)+state
        → 【目付検分=舌前最終・全量】→ 差し戻しなら版+1訂正 → 【再検分(スコープ=検分書定義)】→ 可 → commit
Stage4: 駐機(版固定)。舌の応答6種を待つ。
```

## 落とし穴(実測済み)
1. **サブエージェントの戻り値だけで完了と判断しない**(S2-01部分完了の見逃し)——台帳の独立再計数は目付必須。
2. **壺師の転記・要約は最大欠陥工程**(2壺連続9件)——数値・計数は正本参照方式(文書に数字を再転記せず計数表を指す)。からくり等の要約は原文の機構を変えない(不存在要素の付加が実測された)。
3. タグ表記([未検証])はプロンプトで表記統一を明示([仮定]等の揺れが計数を壊す)。
4. 検分指示は定型書式で(壺師の申告を混ぜた指示は監査を歪める)。
5. commitは着弾ごと小刻みに(部分完了・クラッシュからの再開点を残す)。
6. 乱数はseed+手順を必ずstateに記録(shuf+openssl-ctr等の再現可能な方式)。
