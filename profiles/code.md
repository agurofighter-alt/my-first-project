# profiles/code.md — コード壺(v1.4/GEN-3・GEN-4)

## テストの法(最重要)
- **法の所有者=壺師**:受入テスト(acceptance)は Stage0 で壺師が書き、shared_context に**版付きで同梱**する。蟲師はこれに対して緑にする。
- 蟲師の自作テストは**非権威**(参考出力)。自作テストの緑は通過根拠にならない。
- 受入テストの**モック化・改変は物理/校則KILL相当の違反**。目付が test diff を照合する。

## 死因カテゴリ表
| カテゴリ | 定義 |
|---|---|
| ビルド | build/lint が通らない |
| 受入 | 壺師の受入テストが赤 |
| 与件 | 依存ライセンス違反・禁止依存・対応環境外(Stage0与件) |
| 保守崩壊 | 内部整合の破綻(インターフェース記述と実装の矛盾等)。※「読みにくい」等の好みでは書けない |

## 「実質同じ」(重複判定)
同一インターフェース × 同一アプローチ族(アルゴリズム/依存の系が同じ)。実装の字面差は同一。

## 課の職掌
からくり=設計発想(構造の発明)/関所=セキュリティ・ライセンス/算盤=計算量・メモリ・依存コストの**実数**/橋渡し=API互換・統合手順。

## 安全帳票の対象領域
セキュリティ(認証・入力検証)・データ破壊(削除/移行)・外部送信(テレメトリ/秘密情報)。

## 客観フィルタ
`test`(受入)/`lint`/ビルド を蟲師の中で完了し、pass/fail と算式(計測値)を progress に残す。
