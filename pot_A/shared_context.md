# shared_context.md — pot_A(読み取り専用・全蟲師共通)

> これは壺の定義。蟲師はこれと自分の task だけを見る。他の蟲・他progress・キルログは見ない(＝密閉)。

## 審査テーマ
中学の文化祭で、**1クラスが出す「出し物」**を1匹の蟲として生成する。
- **形式は問わない**:食/非食/お化け屋敷/ゲーム/展示/上演/体験、なんでも可。
- 同じ壺の中で全形式を殺し合わせる。

## センス軸
**未宣言**。この壺では舌(省吾)が軸を降ろしていない。→ **theme only で回す**。
- 軸なしで客観三値だけで足切りできるか＝封印原則が実装レベルで立つか、の最初のテスト。

## 出力フォーマット(1匹 = この3要素セット必須)
```
名前:
仕組み:(2〜3文。その教室で客が何を体験するか)
想定される死因:(1〜2文。校則/消防/衛生/回転/コンセプト崩壊 のどれで死ぬか)
```

## 客観三値triage(生成した各匹に必ず1つ付ける)
- **通過** — 3要素が揃い、物理・校則で不可でなく、既出と丸被りでない。
- **重複KILL** — 自分のバッチ内の既出と実質同じ。
- **物理/校則KILL** — 消防(暗幕で避難動線を塞ぐ等)・食品衛生・照明規定・無人運営など前提が破綻。

## 封印(生成にも選別にも一切降ろさない)
- 集客数・売上・"客が喜ぶか"・市場ウケ・事業性は **見ない**。それはレイヤー2で初めて見る。
- 「強い/光る/面白い」の審美判定も **しない**。それは頂点の舌だけの仕事。
- triage は純・客観(形式・物理・校則・重複)のみ。
